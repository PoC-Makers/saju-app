# 사주 계산 조사 — 쉬운 버전

> 자세한 기술 버전: [원문](./2026-09-13-saju-core-calculation-research.md)
> 이 문서는 사주도 개발도 처음인 사람을 위한 풀어쓴 버전입니다. 결론과 수치는 원문과 같습니다.

## 한 줄 요약

**사주 8글자를 정확히 계산하려면 "시계 시각"이 아니라 "실제 해의 위치"를 기준으로 해야 하고, 그 어려운 부분은 검증된 도구에 맡긴다.**

---

## 이게 왜 필요해?

사주 계산은 **틀려도 그럴듯해 보입니다.** 화면에 `갑자`가 나오든 `을축`이 나오든 일반인은 맞는지 알 수 없어요.
그런데 시각이 30분만 어긋나도 **시간 기둥이 통째로 바뀌고**, 그러면 풀이 전체가 달라집니다.

이 문서는 계산 엔진을 만들기 전에 "어디서 틀리기 쉬운지"를 미리 조사한 결과입니다.
조사한 것은 네 가지입니다.

| | 질문 | 다루는 기둥 |
|---|------|------------|
| ① | 날짜 → 날짜 기둥은 어떻게 구하지? | 일주 |
| ② | 태어난 시각은 어떤 시계로 재야 하지? | 시주 |
| ③ | 사주의 한 해·한 달은 언제 시작하지? | 연주·월주 |
| ④ | 음력 생일은 어떻게 처리하지? | 전부 |

---

## 결론부터

- **시계 시각을 그대로 쓰지 않는다.** 실제 해의 위치로 고친 시각(진태양시)을 쓴다.
- **한국 시간의 역사는 직접 정리하지 않는다.** 전 세계가 함께 관리하는 시간대 데이터(tz DB)에 이미 다 들어 있다.
- **절기(계절의 마디)는 천문 계산 도구로 구한다.** → `astronomy-engine`
- **음력은 한국 기준 도구를 쓴다.** 중국 음력과 윤달 위치가 다르기 때문.
- **날짜 기둥 계산법은 확정.** 150년치 55,152일을 전부 대조해서 하나도 틀리지 않았다.

## 1. 날짜 기둥(일주) — 60일마다 한 바퀴

### 60개 글자 조합이 도는 원리

> 🏣 **비유: 맞물린 톱니바퀴 두 개**
> 10칸짜리 톱니(천간: 갑을병정무기경신임계)와 12칸짜리 톱니(지지: 자축인묘진사오미신유술해)가 맞물려 하루에 한 칸씩 돕니다.
> 두 톱니가 처음 자리로 동시에 돌아오는 데 **60일**이 걸려요. 그래서 조합이 60개입니다(60갑자).

```
1일째: 갑자 → 2일째: 을축 → 3일째: 병인 → ... → 60일째: 계해 → 다시 갑자
```

연·월·시 기둥은 정해진 규칙으로 구할 수 있지만, **날짜 기둥만은 규칙이 없습니다.** 수천 년 동안 하루도 끊기지 않고 돌아온 순환이라, "어느 기준일로부터 며칠 지났나"를 세는 수밖에 없어요.

### 날짜를 숫자 하나로 바꾸기

날짜를 세기 쉽게, 천문학에서 쓰는 **율리우스 일수(JDN)** 를 씁니다. 아주 먼 과거의 어느 날부터 "오늘이 몇 번째 날인지" 매겨 놓은 번호예요.
이 번호를 10으로 나눈 나머지로 윗글자를, 12로 나눈 나머지로 아랫글자를 구합니다.

```ts
const stemIndex   = (jdn + 9) % 10;   // 0이면 갑
const branchIndex = (jdn + 1) % 12;   // 0이면 자
```

### 정말 맞아? — 55,152일 전부 확인

서로 전혀 다른 두 방법으로 계산해서 비교했습니다.

| | 방법 |
|---|------|
| A | 위의 숫자 계산 |
| B | 한국천문연구원(KASI) 자료를 담은 라이브러리 |
| 비교 기간 | 1900년 1월 1일 ~ 2050년 12월 31일 (**55,152일**) |
| 결과 | **틀린 날 0일** |

> 💡 **조사 중 헷갈렸던 것**: 처음엔 "1984년 2월 2일 = 갑자일"이라는 자료와 계산이 이틀 어긋났습니다.
> 알고 보니 1984년은 **갑자년**(해의 기둥)이었지 그날이 갑자**일**은 아니었어요. 실제 그날은 병인일입니다.
> 사주 자료에서 흔한 함정 — **"널리 알려진 숫자"도 검증 없이 쓰면 안 됩니다.**

- 날짜 기둥은 **달력 날짜만으로** 정해집니다. 아래 2장의 시간 보정이 날짜 기둥을 바꾸지는 않아요.
- 예외: 밤 11시~12시생을 "오늘"로 볼지 "내일"로 볼지(2.4)는 날짜 기둥에 직접 영향을 줍니다.

### 만들 때 조심할 점

- 컴퓨터의 날짜 기능은 **사는 지역의 시간대가 몰래 끼어들어** 하루가 밀리는 사고가 납니다. 그래서 세계 표준시(UTC) 기준 정수로만 계산합니다.
- 소수점 계산은 오차로 하루가 밀릴 수 있어서 **정수 나눗셈**을 씁니다.
- JavaScript에서 `-3 % 60`은 `-3`이 나옵니다(음수). 그래서 `((n % 60) + 60) % 60`처럼 항상 양수가 되게 합니다.

## 2. 시간 기둥(시주) — 시계가 아니라 해를 본다

### 사주의 시각은 2시간 단위

하루 24시간을 2시간씩 12칸으로 나눠 지지 12개를 붙입니다.

```
자시 23~01 │ 축시 01~03 │ 인시 03~05 │ 묘시 05~07 │ 진시 07~09 │ 사시 09~11
오시 11~13 │ 미시 13~15 │ 신시 15~17 │ 유시 17~19 │ 술시 19~21 │ 해시 21~23
```

여기서 말하는 시각은 **시계 시각이 아니라 "해가 실제로 어디 있는지"로 잰 시각(진태양시)** 입니다.
옛날 사람들은 해시계로 시간을 쟀으니까요. 해가 하늘 꼭대기에 있을 때가 낮 12시입니다.

### 왜 시계 시각과 다를까? — 이유 두 가지

**(a) 한국 시계는 일본 기준으로 맞춰져 있다**

한국 표준시는 동경 **135도**(일본 근처)를 기준으로 합니다. 그런데 서울은 동경 **약 127도**에 있어요.
경도 1도 차이 = 4분이라서, 서울에서 해가 꼭대기에 오는 건 시계로 **약 12시 32분**입니다.

그래서 흔히 "시계 시각에서 32분 빼면 된다"고 하는데, **그것만으로는 틀립니다.** 두 가지가 더 있어요.

- **기준 경도가 시대마다 바뀌었다** — 32분은 지금(135도 기준)에만 맞는 값입니다.
- **해의 속도가 1년 내내 일정하지 않다** — 아래 (b)

**(b) 해는 정확한 시계가 아니다 — 균시차**

지구는 해 주위를 완벽한 원이 아닌 **찌그러진 타원**으로 돌고, 자전축도 **기울어져** 있습니다.
그래서 해가 꼭대기에 오는 시각이 날마다 조금씩 달라져요. 1년 동안 **−14분 ~ +16분**, 최대 30분 폭으로 흔들립니다.
이 차이를 **균시차**라고 부릅니다. 시간 기둥은 2시간 단위라, 30분이면 경계를 충분히 넘어갑니다.

### 한국 시간은 몇 번이나 바뀌었다

| 시기 | 한국 시계 | 이유 |
|------|-----------|------|
| 1910년경 | UTC+8:30 | 대한제국 표준시 (127.5도 기준) |
| 일제강점기 | UTC+9:00 | 일본 표준시 (135도 기준) |
| 1954-03-21부터 | UTC+8:30 | 127.5도 기준으로 복귀 |
| 1961-08-10부터 | UTC+9:00 | 다시 135도 기준 (지금까지) |

여기에 **서머타임**(여름에 시계를 1시간 앞당기는 제도)도 있었습니다: **1948~1951, 1955~1960, 1987~1988년.** (1987~88년은 서울올림픽 대비)

> 💡 **이 역사를 직접 표로 만들지 않습니다.** 손으로 만든 표는 반드시 어딘가 틀립니다.
> 전 세계 컴퓨터가 함께 쓰고 검증하는 **시간대 데이터(tz DB)** 에 이미 정확히 들어 있다는 걸 직접 조회해서 확인했어요. Node.js에 기본으로 들어 있어서 따로 설치할 것도 없습니다.

### 올바른 계산 순서

```
① 시계 시각 → 세계 표준시(UTC)로 바꾸기    시간대 데이터가 표준시 변경·서머타임을 알아서 처리
② 세계 표준시 → 태어난 곳 기준 평균 시각   경도만큼 더하기 (경도 ÷ 15 = 시간)
③ 평균 시각 → 진짜 해의 시각(진태양시)     균시차 더하기
④ 진태양시 → 몇 시(자·축·인…)인지 판정
```

> 💡 **이 순서의 장점**: ②에서 **태어난 곳의 경도를 직접** 쓰기 때문에 "그 시절 기준이 몇 도였는지" 따질 필요가 없습니다.
> 1958년생이든 2026년생이든 **같은 코드 한 줄**이 맞는 답을 냅니다.

- 균시차는 3장의 `astronomy-engine` 도구로 함께 구합니다.
- 태어난 곳 경도도 중요합니다. 서울로 고정하면 제주·독도 출생자는 **20분 이상** 어긋날 수 있어요.
  지금은 서울로 시작하되, 엔진은 경도를 입력으로 받게 만들어 나중에 지역 선택을 붙일 수 있게 했습니다.

### 밤 11시~12시생은 오늘일까 내일일까? — 야자시

자시는 **밤 11시~새벽 1시**로, 자정을 사이에 두고 이틀에 걸쳐 있습니다.
그래서 **밤 11시~12시** 사이(야자시)에 태어난 사람의 날짜 기둥을 어느 날로 볼지 학파마다 다릅니다.

| 방식 | 밤 11~12시생의 날짜 기둥 |
|------|-------------------------|
| `keep-day` (날짜는 자정에 바뀐다) | **오늘** 날짜 그대로 |
| `next-day` (하루는 자시에 시작한다) | **내일**로 넘김 |

**정답이 없는 문제**라서, 엔진은 둘 다 고를 수 있게 **옵션**으로 만들었습니다. 기본값은 **`keep-day`(오늘)** 로 정했습니다.
결과 화면에도 "어느 방식으로 계산했는지" 표시해서 사용자가 믿을 수 있게 할 예정입니다.

> 💡 이 판정은 반드시 **진태양시로 고친 다음**에 해야 합니다. 순서를 거꾸로 하면 밤 11시 전후 출생자가 통째로 틀려요.

## 3. 연·월 기둥 — 사주의 새해는 1월 1일이 아니다

### 한 해는 입춘에 바뀐다

사주에서 해가 바뀌는 날은 1월 1일도, 설날도 아닌 **입춘**(2월 3~5일 무렵)입니다.

| 태어난 날 | 연 기둥 |
|-----------|---------|
| 2026년 2월 3일 | 아직 **을사**(2025년) |
| 2026년 2월 5일 | **병오**(2026년) |

입춘 날짜는 해마다 2월 3~5일 사이에서 **움직이기 때문에** 날짜를 고정해 둘 수 없고, 매번 계산해야 합니다.

### 한 달도 "절기"로 바뀐다

1년에는 계절의 마디인 **24절기**가 있습니다. 그중 **12개(절)** 가 사주의 달이 바뀌는 날입니다.
절기는 "해가 하늘에서 특정 위치(각도)에 도달하는 순간"이에요.

| 절기 | 대략 날짜 | 시작되는 달 |
|------|-----------|-------------|
| 입춘 | 2월 4일경 | 인월 |
| 경칩 | 3월 6일경 | 묘월 |
| 청명 | 4월 5일경 | 진월 |
| 입하 | 5월 6일경 | 사월 |
| 망종 | 6월 6일경 | 오월 |
| 소서 | 7월 7일경 | 미월 |
| 입추 | 8월 8일경 | 신월 |
| 백로 | 9월 8일경 | 유월 |
| 한로 | 10월 8일경 | 술월 |
| 입동 | 11월 7일경 | 해월 |
| 대설 | 12월 7일경 | 자월 |
| 소한 | 1월 6일경 | 축월 |

> (날짜는 이해를 돕기 위한 대략값입니다. 실제로는 해마다 계산합니다.)

### 해의 위치는 어떻게 계산해? — `astronomy-engine`

해의 위치는 천문 계산이 필요해서 검증된 도구 **`astronomy-engine`** 을 쓰기로 했습니다.

- "해가 이 각도에 도달하는 순간"을 바로 찾아주는 기능이 있어 절기 계산에 딱 맞습니다.
- 오차가 **분 단위 이내**로 충분히 정확합니다.
- 다른 도구에 기대지 않아 엔진을 가볍게 유지할 수 있습니다.
- 2장의 **균시차도 같은 도구로** 구할 수 있어, 도구 하나로 두 문제를 해결합니다.
- 비교했던 `suncalc`는 가볍지만 이런 정밀 검색 기능이 없어서 뺐습니다.

### 월·시 기둥의 윗글자는 "표"로 정해진다

아랫글자(지지)가 정해지면 윗글자(천간)는 계산이 아니라 **정해진 표**를 보고 찾습니다.

- **달의 윗글자** ← **해의 윗글자**로 정해짐 (오호둔이라는 표)
- **시간의 윗글자** ← **날의 윗글자**로 정해짐 (오서둔이라는 표)

> 💡 시간 기둥이 **날짜 기둥에 따라** 정해지므로, 야자시 선택으로 날짜 기둥이 바뀌면 **시간 기둥도 따라 바뀝니다.** 그래서 둘은 항상 함께 테스트합니다.

## 4. 음력 생일

### 왜 필요해?

어르신 세대는 생일을 **음력**으로 기억하는 경우가 많습니다. 국내 사주 서비스라면 사실상 필수 기능이에요.

### 한국 음력 ≠ 중국 음력

둘 다 달의 모양을 기준으로 하지만, **한국은 한국 시간, 중국은 중국 시간**으로 날짜를 판정합니다.
그래서 경계에 걸린 해에는 **날짜가 하루 어긋나거나 윤달 위치가 달라집니다.**

> 💡 **중국 라이브러리를 쓰면 안 됩니다.** 사주 기능까지 들어 있어 편해 보이지만 결과가 한국 사주와 어긋나요.

### 후보 도구 (모두 한국천문연구원 자료 기반)

| 도구 | 지원 기간 | 특징 |
|------|-----------|------|
| `korean_lunar_calendar_js` | 1000년 ~ 2050년 | 기간이 가장 넓음 |
| `korean-lunar-calendar` | — | 1장 날짜 기둥 검증에 쓴 도구. 신뢰성 확인됨 |
| `kor-lunar-js` | 1890년 ~ 2050년 | 윤달 옵션 명확 |
| `manseryeok` | 1391년 ~ 2100년 | TypeScript, 한·중 윤달 차이 보정 |

고르는 기준: 윤달 지원 · 1900~2050년 커버 · TypeScript 지원 · 관리가 잘 되는지 · 라이선스.
후보 2~3개에 **같은 날짜를 넣어 결과를 비교**해 보고, 다르면 한국천문연구원 원본을 정답으로 봅니다. **아직 고르지 않았습니다.**

### 윤달 — "몇 월 며칠"만으로는 부족하다

음력에는 같은 달이 두 번 오는 **윤달**이 있습니다. 그래서 "음력 4월 10일"만으로는 평달 4월인지 윤 4월인지 알 수 없어요.
입력에 **윤달 여부를 꼭** 함께 받습니다. 그해에 윤달이 없으면 화면에서 윤달 체크를 막습니다.

> 💡 **음력은 입력할 때만 씁니다.** 받자마자 양력으로 바꾸고, 엔진 안쪽은 양력 하나로만 계산합니다. 음력이 안쪽까지 들어오면 복잡도가 폭발해요.

## 따라 해보기 — 가상의 한 사람 계산하기

> 실제로 만든 엔진(`@saju/core`)에 넣어 돌린 결과입니다. 생년월일은 가상의 예시입니다.

**입력**: 1995년 3월 15일 오후 2시 30분, 서울(동경 126.978도) 출생

**① 시각 고치기 (2장)**

| 단계 | 값 |
|------|----|
| 시계 시각 | 14:30 |
| 진태양시 | **13:48** |

42분이 빠졌습니다. 경도 차이 약 32분 + 3월 중순의 균시차 약 10분입니다.

**② 시간 확인 (2장)**: 13:48은 13~15시 사이 → **미시**

**③ 연 기둥 (3장)**: 3월이라 입춘이 지났음 → 1995년 → **을해**

**④ 월 기둥 (3장)**: 3월 15일은 경칩(3월 6일경) 이후 → 묘월 → 표에서 윗글자를 찾으면 **기묘**

**⑤ 날짜 기둥 (1장)**: 1995-03-15의 JDN으로 계산 → **을사**

**⑥ 시간 기둥 (3장)**: 날의 윗글자 `을` + 미시 → 표에서 찾으면 **계미**

**결과**

| 시주 | 일주 | 월주 | 연주 |
|------|------|------|------|
| 계미 | 을사 | 기묘 | 을해 |

### 보정을 안 하면 어떻게 될까?

같은 날 **오후 1시 20분**생을 계산해 보면:

| | 시계 시각으로 판정 | 진태양시로 판정 |
|---|---|---|
| 시각 | 13:20 | **12:38** |
| 몇 시? | 미시 (13~15시) | **오시 (11~13시)** |
| 시주 | 계미 ❌ | **임오** ✅ |

시계만 보면 미시인데, 실제 해의 위치로는 아직 오시입니다. **보정 하나로 시간 기둥이 바뀝니다.** 이 문서가 존재하는 이유예요.

### 태어난 시각을 모르면?

시각 없이 날짜만 넣으면 **연·월·일 기둥 3개만** 계산합니다(을해 · 기묘 · 을사). 시간 기둥은 아무 시각으로나 채우지 않고 **비워 둡니다.**
단, 태어난 날 **당일에 절기가 바뀌면** 시각 없이는 월 기둥을 정할 수 없어서, 시각을 꼭 입력해 달라고 안내합니다.

## 계산 흐름 전체 그림

```
[입력] 생년월일시 · 양력/음력 · 태어난 곳 · 성별
   │
   ├─ 음력이면 → 양력으로 변환
   ├─ 시계 시각 → 세계 표준시 (시간대 데이터)
   ├─ 세계 표준시 + 경도 + 균시차 → 진태양시
   ├─ 절기 시각 계산 (해의 위치)
   │
   ├─ 연 기둥 ← 입춘 기준
   ├─ 월 기둥 ← 12절기 + 표
   ├─ 날짜 기둥 ← JDN을 60으로 나눈 나머지 + 야자시 옵션
   └─ 시간 기둥 ← 진태양시 + 표 (날짜 기둥에 따라 달라짐)
```

이 흐름은 엔진의 폴더 구조(`calendar/` → `pillars/`)와 그대로 맞습니다.

## 어떻게 맞는지 확인해?

사주 계산은 틀려도 눈으로 알 수 없기 때문에 **외부 정답지**가 꼭 필요합니다.

1. **한국천문연구원 만세력을 정답지로** 씁니다.
2. **경계에서 주로 틀립니다.** 평범한 날은 대충 짜도 맞아요. 그래서 이런 날을 집중적으로 테스트합니다.
   - 입춘 전후 (연 기둥이 바뀜)
   - 각 절기 전후 (월 기둥이 바뀜)
   - 밤 11시 ~ 새벽 1시 (자시, 날짜 기둥이 바뀜)
   - 진태양시 보정으로 시간 기둥이 넘어가는 경우 (위 따라 해보기처럼)
   - 서머타임 시기(1955~1960, 1987~1988) 출생
   - 표준시가 바뀐 날(1954-03-21, 1961-08-10) 전후
   - 윤달 생일
3. 이 경우들을 정답과 함께 **고정된 테스트 데이터**로 만들어, 나중에 코드를 고쳐도 계산이 틀어지지 않게 지킵니다.

## 용어 사전

| 용어 | 뜻 |
|------|----|
| 천간 | 기둥의 윗글자. 갑을병정무기경신임계 10개 |
| 지지 | 기둥의 아랫글자. 자축인묘진사오미신유술해 12개 |
| 60갑자 | 천간 10 × 지지 12가 맞물려 생기는 60개 조합 |
| 일주·시주·월주·연주 | 날짜·시간·달·해의 기둥 |
| 일간 | 날짜 기둥의 윗글자 |
| JDN (율리우스 일수) | 먼 과거부터 하루에 1씩 매긴 날짜 번호 |
| UTC | 세계 표준시. 한국은 보통 UTC보다 9시간 빠름 |
| 표준시 / 표준자오선 | 나라가 정한 공식 시계 / 그 기준이 되는 경도 (한국은 지금 135도) |
| 경도 | 지구의 동서 위치. 1도 차이 = 시간 4분 차이 |
| 진태양시 | 실제 해의 위치로 잰 시각. 해가 꼭대기면 12시 |
| 평균태양시 | 해가 1년 내내 일정하게 움직인다고 가정한 시각 |
| 균시차 | 진태양시와 평균태양시의 차이. 1년 동안 −14 ~ +16분 |
| 서머타임 | 여름에 시계를 1시간 앞당기는 제도 |
| tz DB (시간대 데이터) | 전 세계 시간대의 변경 역사를 담은 공용 데이터 |
| 자시 | 밤 11시 ~ 새벽 1시 |
| 야자시 | 자시 중 밤 11시 ~ 12시 부분 |
| 유파 | 사주를 해석하는 학파 |
| 절기 / 24절기 | 해의 위치로 나눈 계절의 마디 / 그 24개 |
| 절 (12절) | 24절기 중 사주의 달이 바뀌는 12개 |
| 입춘 | 2월 초 절기. 사주의 새해 첫날 |
| 태양 황경 | 하늘에서 해의 위치를 각도로 나타낸 값 |
| 오호둔 / 오서둔 | 달의 윗글자 / 시간의 윗글자를 찾는 표 |
| 윤달 | 음력에서 같은 달이 한 번 더 오는 달 |
| 삭망월 | 달이 한 번 차고 기우는 주기 (약 29.5일) |
