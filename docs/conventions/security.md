# 보안 컨벤션

이 저장소는 **public**이다. 한 번 올라간 것은 히스토리·이슈·PR에 영구히 남고, 삭제해도 이미 복제·색인됐을 수 있다.
**공개되는 모든 것은 올리기 전에 검증한다.**

## 1. 절대 올리지 않는 것

| 분류 | 예 |
|------|-----|
| 인증 정보 | API 키, 액세스 토큰, 시크릿, 비밀번호, JWT 시크릿, OAuth client secret |
| 인증서·키 | `.pem` `.key` `.p12` `.pfx` `.jks` `.crt`, SSH 개인키, `BEGIN ... PRIVATE KEY` |
| 접속 정보 | DB 접속 문자열(계정·비밀번호 포함), 내부 호스트·IP, 관리 콘솔 URL |
| 환경 파일 | `.env`, `.env.*` (단 `.env.example`은 **값 없이** 키 이름만) |
| 개인정보 | 실명·전화번호·주소·생년월일 등. 테스트 데이터도 실제 값 금지 |
| 회사 정보 | 사내 문서명·시스템명·고객사명·내부 URL |

## 2. 커밋 전 검증 (필수)

**모든 커밋 전에** 스테이징된 변경을 확인한다.

```bash
git diff --cached                    # 무엇이 올라가는지 눈으로 확인
git diff --cached --name-only        # 파일 목록
```

패턴 검사:

```bash
git diff --cached | grep -inE \
  'api[_-]?key|secret|password|passwd|token|BEGIN [A-Z ]*PRIVATE KEY|ghp_|github_pat_|AKIA[0-9A-Z]{16}|xox[baprs]-|sk-[A-Za-z0-9]{20,}'
```

- **자동화 예정**: husky + lint-staged 도입 시 이 검사를 pre-commit 훅으로 건다 (→ `docs/setup-todo.md`).
- 값 대신 **환경변수로 참조**한다. 예시가 필요하면 `.env.example`에 **키 이름만**.

## 3. 이슈·PR·문서 검증

이슈·PR 본문, 코드블록, 로그 붙여넣기, **스크린샷**도 전부 공개된다.

- 로그를 붙일 때 **토큰·쿠키·Authorization 헤더·커넥션 문자열**을 지운다.
- 에러 메시지에 경로가 포함되면 사용자명(`/Users/이름/...`)을 확인한다.
- 스크린샷에 브라우저 탭·터미널 프롬프트·환경변수 창이 찍히지 않았는지 본다.
- 실제 개인정보 대신 **가상의 예시 값**을 쓴다.

## 4. 스크립트·설정 파일

- 스크립트에 토큰을 하드코딩하지 않는다. `gh` CLI 인증이나 환경변수를 쓴다.
- 저장소·조직 이름 외의 **식별자(계정 ID, 내부 리소스 ARN 등)를 커밋하지 않는다.**

## 5. 이미 올라갔다면

커밋을 지워도 **이미 노출된 값 자체는 계속 유효**하다. 공개 저장소의 키는 봇이 수 분 내에 수집해 가므로 시간이 곧 피해다.

1. **먼저 사용자에게 알린다** — 무엇이 어디에(커밋·이슈·PR·스크린샷) 노출됐는지 즉시 보고한다.
   임의로 폐기하거나 히스토리를 재작성하지 않는다. 그 자격증명이 어디에 쓰이는지는 사용자만 안다.
2. **폐기(rotate) 여부를 권한 기준으로 판단**한다.

   | 노출된 것 | 판단 |
   |---|---|
   | 쓰기·삭제 권한 (DB 접속, AWS 키, 결제 키) | **즉시 폐기.** 서비스 중단이 유출 피해보다 낫다 |
   | 개인정보 접근 가능 | **즉시 폐기.** 법적 책임까지 걸린다 |
   | 읽기 전용·저권한 | 계획된 교체 가능 (그래도 빠를수록 좋다) |

3. 가능하면 **새 키 발급 → 배포 → 옛 키 폐기** 순서로 무중단 교체한다.
   키를 하나만 지원하는 서비스라면 짧은 다운타임을 감수하고 폐기한다.
4. 필요하면 히스토리에서 제거 (`git filter-repo` 등) — 단 이미 클론된 사본은 회수 불가.
5. 재발 방지 규칙을 이 문서에 추가한다.

## 6. 저장소 공개 상태

- 현재 **public** — 무료 플랜에서 브랜치 보호(ruleset)를 쓰기 위한 선택.
- 유료(Pro/Team) 전환 시 private으로 되돌린다. 그전까지는 이 문서의 규칙을 특히 엄격히 지킨다.
- 커밋 작성자 이메일도 공개된다. 개인 메일 노출이 부담되면 GitHub의 `noreply` 이메일로 설정한다.
